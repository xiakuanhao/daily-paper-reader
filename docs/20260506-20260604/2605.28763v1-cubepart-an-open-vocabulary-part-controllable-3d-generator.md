## 摘要
在游戏和仿真中使用的交互式3D资产通常被分解为特定的语义部件，以支持动画、物理和脚本行为，然而大多数生成式3D模型要么生成整体网格，要么生成任意的部件分解，无法与特定应用需求对齐。我们提出了CubePart，一个面向开放词汇、部件可控的3D网格生成框架，该框架将部件结构作为推理时的显式控制信号。给定一个全局文本提示和用户定义的部件模式（以开放式部件名称列表表示），我们的方法生成一组网格——每个模式元素对应一个——这些网格组装成一个连贯的物体，同时遵循指定的语义结构。为了实现这一能力，我们引入了一个可扩展的数据流水线，用于构建一个大规模的开放词汇、带部件标签的3D数据集，以及一个两阶段生成架构，将全局形状合成与部件级解码分离开来。我们证明，生成的资产可以直接集成到游戏引擎中，并通过动画和行为脚本驱动，无需手动后处理。项目页面：https://cubepart.github.io/

## Abstract
Interactive 3D assets used in games and simulation are typically decomposed into specific semantic parts to support animation, physics, and scripted behaviors, yet most generative 3D models produce either monolithic meshes or arbitrary part decompositions that cannot be aligned with application-specific requirements. We present CubePart, a generative framework for open-vocabulary, part-controllable 3D mesh generation that exposes part structure as an explicit inference-time control signal. Given a global text prompt and a user-defined parts schema expressed as an open-ended list of part names, our method generates a set of meshes - one per schema element - that assemble into a coherent object while respecting the specified semantic structure. To enable this capability, we introduce a scalable data pipeline to construct a large open-vocabulary, part-labeled 3D dataset, along with a two-stage generative architecture that separates global shape synthesis from part-level decoding. We demonstrate that the resulting assets can be directly integrated into game engines and driven by animation and behavior scripts without manual post-processing. ## 1. 论文的核心问题与整体含义
- **研究背景**：现代游戏、仿真等交互应用中，3D 资产必须按语义部件分解（如车轮、车灯、肢体），以驱动动画、物理与脚本行为。
- **现有问题**：
  - 多数 3D 生成模型仅输出整体网格或任意部件分割，缺乏对语义结构的显式控制。
  - 基于 2D 分割的部件控制方法无法处理遮挡部件，且视图依赖、难以精确对应 3D 结构。
  - 闭合词汇数据集与固定部件分类难以满足多样化的下游需求。
- **核心意图**：提出一种 **开放词汇、部件可控的 3D 生成框架**，让用户通过文本提示和部件名称列表直接定义目标物体的部件结构，生成可直接被游戏引擎使用的多部件网格。

## 2. 论文提出的方法论
### 2.1 整体框架（CubePart）
- **输入**：全局文本描述（如「一辆水母主题的赛车」）及部件模式（如 `{车体, 前左轮, …}`）。
- **输出**：一组一一对应模式元素的独立网格，组装后构成完整物体。

### 2.2 两阶段生成架构
- **阶段一：整体网格生成**
  - 基于 Vecset 扩散模型（Multi-Modal Diffusion Transformer, MM-DiT），以 Qwen-VL 编码文本条件。
  - 预训练于 470 万 mesh-text 对，再通过“schema‑aware fine‑tuning”确保生成网格包含所有指定部件。
  - 训练目标：流匹配损失，公式 \( L = \mathbb{E}_{(Z_0,c),Z_1,t} \| f_\theta(Z_t, t, c) - v_t \|^2 \)。
- **阶段二：多部件网格生成**
  - 接受阶段一的整体形状隐编码，将其分解为多个部件隐编码。
  - **部件感知提示**：给定整体部件列表和目标部件名，引导模型聚焦特定部件。
  - **交叉部件注意力块**：在预训练的局部注意力层之间插入零初始化的 Transformer 块，实现部件间信息交互，同时保留预训练几何先验。
  - 利用阶段一权重初始化，仅微调新增的交叉注意力块。

### 2.3 大规模开源部件数据集构建
- **规模**：462K 资产，2.02M 部件（约为 PartVerse‑XL 的 11 倍）。
- **自动化数据引擎**：
  - 预处理：过滤缺陷几何，保留 2‑32 部件的资产。
  - VLM 质量过滤：剔除扫描噪声、非独立物体等。
  - **SoM（Set-of-Mark）标注**：多视角（14个）渲染，每视角生成纹理图与分色部件图，并对部件编号。
  - VLM（GPT‑5）同时接收多对视图，聚类并赋予简洁的语义部件名（非描述性标题）。
  - 后处理：水密化网格，点采样用于训练。

## 6. 主要结论与发现
- 所提 CubePart 框架首次实现了 **开放词汇、文本可定义的部件可控 3D 生成**。

- 生成的多部件网格无需后处理即可直接集成到游戏引擎，被脚本驱动的动画和行为（如车轮转向、武器射击、螺旋桨旋转等）正确响应。

## 7. 优点
- **首创性**：首个支持任意文本部件模式的 3D 生成框架，打通了生成模型与下游行为控制之间的鸿沟。
- **数据引擎**：提出 SoM 增强的 VLM 标注流程，以全自动方式构建迄今最大规模的开放词汇 3D 部件数据集，命名质量优于现有数据集。
- **架构设计**：零初始化交叉部件注意力在保留预训练几何先验的同时实现部件交互，比直接修改原注意力层更稳定有效。
- **工程实用性**：端到端验证了从文本到可行为驱动资产的全流程，并提供真实游戏平台中的脚本示例。

## 8. 不足与局限
- **变形部件缺失**：仅支持刚体部件，未涉及蒙皮或顶点权重，无法生成可变形角色。
- **几何穿透残留**：尽管交叉注意力显著减少，部件交界处仍存在少量重叠。
- **空间方位混淆**：数据集采用 VLM 自动标注，左/右、前/后等方位词偶有错误，导致模型有时交换对称部件。
- **复杂几何丢失**：输入几何过于复杂时，可能遗漏部分部件或细节。
- **评价维度单一**：未进行用户主观评估，仅依赖 CD 和 F‑score 几何指标，缺乏纹理或行为层面的量化实验。
- **依赖特定 VLM**：数据质量受限于 GPT‑5 的能力，若更换模型可能引入标注偏差。
